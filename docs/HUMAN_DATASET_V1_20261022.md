# 真人手物体长序列数据集建设与训练前验收

本阶段先建设数据，不启动新一轮模型训练。已有六段 DexYCB、436 帧的结果只作为工程烟测；不把这些短片重新随机切分成“新测试集”。正式联合手部与物体预测的数据验收通过后，才构建训练窗口、训练和评测。

本次GitHub同步范围仅为数据阶段文档。本文记录本地/服务器工作区的实际结果；新增工具代码、测试代码、数据、权重和 `runs/` 产物不随本次文档提交发布。文中1,081项测试指该工作区，而不是仅检出本次文档commit即可获得的测试集合。

## 数据分层

| 数据池 | 用途 | 必须保留的边界 |
|---|---|---|
| 联合姿态候选池 | 长连续真人 RGB-D、相机标定、对应物体模型、公开手部与物体姿态参考 | 下载成功不等于坐标/时序/标注质量通过 |
| EgoDemo 长视频辅助池 | 第一人称真人交互、配套手部和事件标注、动作与场景多样性 | 缺少物体6D参考、米制深度或对应mesh时，不能充当联合6D基准 |
| 旧开发回归池 | 保持现有提取、叠加、预测代码可运行 | 已参与训练/选模/评估的采集不能回到新的未见test |

HO-Cap 官方提供多被试 RGB-D、标定、物体模型、手部和物体参考；其公开参考采用半自动标注，不宣称完全人工或独立动捕真值。正式采用前必须检查原始参考生成方式和坐标语义。官方逐帧姿态估计任务划分不直接复用为未来预测的跨被试划分，防止同采集邻帧进入不同集合。

该参考流程本身使用MediaPipe、FoundationPose、多视角优化及部分时域插值/平滑。它独立于本项目本轮推理，但不是与这些感知模型完全独立的动捕监督；不能将整段离线优化参考直接当成“在线因果输入”。本项目必须另存当前帧感知估计，参考仅用于train/val监督与test评估，并披露相关参考偏差。

来源依据保存在候选下载证据中；公开数据与工具代码许可证分别记录，不把数据许可证当作工具代码许可证。不可访问的资源只登记为候选，不能绕过访问控制或计入实际下载量。

## 第一版目标与放行门槛

本阶段规模目标为120个通过验收、能用于真人手部＋物体6D联合姿态训练/评测的独立采集，目标train/val/test约84/18/18。120是首阶段规模目标，不是模型精度保证。其余质量和多样性门槛为项目工程协议，不是数据集官方标准。

- 至少120个独立合格采集、6名可核实身份的被试、8种物体、4种有依据的动作。
- 每个有效采集连续至少10秒，优先20–60秒；记录完整采集与实际可用区间，不拼接、不重复帧、不改帧率凑时长。
- 主划分目标 train/val/test 为70/15/15，按被试整组分配。同一采集的机位、切片、转码、相邻窗口和内容别名不得跨组。
- 每次进度报告列出已下载联合候选、已验收联合合格、各split合格数和距120的合格数缺口；不以辅助池、滑窗、重复机位或插值片充数。目标84/18/18不能凌驾于被试/采集隔离。
- 每集合至少 train 60、val 15、test 15 个独立合格采集。组大小造成比例偏差时报告实际比例，不为凑数字拆组。
- 被试未知则保持未知；采集UUID、目录名、物体类别不能替代被试身份。未知身份数据不用于跨被试准确率宣称。
- 统计左右手、单/双手、动作、物体、场景、视角、时长、速度和遮挡分布。暂缺的维度标为待标注；不同镜头不计作额外独立动作采集。
- 稀有类别和未见物体/场景单独列出。跨物体/跨场景泛化另建预注册协议，不混入一个总体数字掩盖差异。

若来源只有三类动作，就如实报告三类并保持未放行；不能从同一类凭空生成第四类。可在训练前补充有证据的子动作标注或正式修订协议，修订必须形成新版本和原因记录。

## 每段数据的验收

1. **身份和来源**：来源版本、许可、采集ID、被试ID及其依据、场景、相机、目标物体、原始路径与SHA256；先审视频实帧确认真人，不依据文件名判断。
2. **真实连续性**：完整解码、逐帧编号、PTS或源时间戳严格递增，记录丢帧、断档、重采样、重复内容；历史窗口和未来目标不得跨断档。
3. **时间对齐**：RGB、depth、手部、物体、相机姿态按原始时间基准对齐。帧率须有官方元数据或实测依据，禁止默认30fps。明确时长使用首末帧跨度还是容器覆盖时长。
4. **几何定义**：记录K、畸变、RGB/depth对齐关系、深度尺度、mesh原点/尺度、坐标轴、矩阵方向和关节顺序。手与物体统一米制相机系后才计算三维关系。世界系手关节与相机系物体变换不能直接相减。
5. **相机运动**：固定相机与第一人称移动相机分开；移动相机必须明确轨迹与运动补偿，否则不进入固定相机未来姿态发布。
6. **参考隔离**：公开参考与本次感知估计分目录。FoundationPose初始化仅使用允许的当前帧输入，不使用未来手/物体参考、测试参考位姿或自动参考对齐。
7. **缺失与质量**：保留NaN和手/物体有效掩码；分别报告人工/公开参考有效率、感知检出率和最终预测覆盖率。不以插值或零填充制造检出。
8. **可视检查**：每个新采集先检查首/中/末帧真人与目标；正式发布还需覆盖至少5%有效帧以及全部自动异常帧，检查左右手、轴向、重投影、遮挡、漂移和时间错位。三张缩略图通过不等于整个序列标注合格。

自动检查、人工审阅、坐标核验分别记录pass/fail/pending。任何必需项pending均不得声称正式联合训练数据已验收。

## 冻结顺序

1. 完整候选台账，区分候选、已下载、真人确认、有效长序列、联合姿态就绪。
2. 记录旧评测暴露采集。基于被试与采集来源冻结候选组划分，而不是基于模型误差选择容易的test。
3. 补齐标注与质检；所有排除都有预注册规则和原因。test标注可用于数据完整性/坐标审计，不用于模型调参、挑相机或筛掉困难帧。
4. 正式发布审计：数量、多样性、实际内容SHA、身份隔离、别名、坐标、时间、质量全部达标；清单与配置冻结不可原地覆盖。
5. 再生成历史→未来窗口。归一化、类别词表和统计仅用train拟合；val用于早停和超参；训练方案锁定后才进行最终test评测。

当前自动台账与冻结工具只负责数据发布，不启动模型，不把候选划分自动转换成可训练清单。

## 训练后的评测预案

正式训练前再冻结精确关节映射、损失、种子与阈值；本阶段不通过观察新test模型误差确定门槛。

- 先分别验收当前帧手部与FoundationPose感知误差，再评估未来预测，区分输入噪声与预测器误差。
- 同时报告持位、因果恒速、LSTM和Mamba；使用相同输入、参考、可评估帧和预测时域。暂定0.25、0.5、1、2秒，每个时域独立统计。
- 米制手部报告相机系MPJPE、腕部平移、根对齐姿态误差及阈值曲线；二维误差单列，不能当三维精度。
- 物体报告平移mm、旋转度、明确对称性规则的ADD/ADD-S等指标；铰接物体不能仅靠单刚体姿态掩盖形变。
- 明确成功事件的联合阈值、分母、参考可用性和漏检处理；输出覆盖率、条件误差和端到端成功率分列。无法独立核验参考时不报告物理准确率。
- 每个被试/采集等权与帧加权都报告；置信区间按独立采集或被试重采样，不能把相邻滑窗当独立试验。
- 汇总不同物体、动作、左右手、遮挡、速度、视角、短/长时域的分层结果。保留全部预注册seed，禁止test挑最优seed。

### 下一阶段的硬性顺序

1. 继续补充独立真人采集，满足至少120个合格采集、train≥60/val≥15/test≥15；补齐场景依据和不足的动作覆盖。120是本项目暂定门槛，不是证明泛化充分的统计保证。
2. 取得HO-Cap本批导出序列的实际时间依据，完成K、深度尺度、关节顺序/左右手、mesh与相机坐标约定和参考质量核验；第一人称联合数据另需可核验的相机运动及补偿。
3. 先验收当前帧感知提取流程，再生成与参考隔离的因果手部/FoundationPose观测及有效掩码；完成每条至少5%有效帧和全部异常帧审查，不靠补零/插值制造覆盖率。
4. 复核泄漏与历史暴露，冻结正式版本并通过全部门禁，才生成窗口、拟合train归一化、训练与val选择；最后仅对锁定模型执行test。任何数据门禁未通过都不跳到训练。
